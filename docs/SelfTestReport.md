# 微信外卖平台 - 自测报告

## 1. 硬性门槛说明

本项目通过执行 docker compose up -d 命令即可一键启动全部服务，无需任何额外的手动配置步骤。启动完成后，管理后台可通过 http://localhost:8081 访问，后端 API 服务运行在 http://localhost:8080 端口。容器编排包含 MySQL 数据库、Redis 缓存、Spring Boot 后端和 Vue 前端管理后台四个服务，各服务间通过健康检查机制确保依赖顺序正确启动，满足 Docker Delivery Standard 的交付标准。

## 2. 交付完整性说明

项目完整实现了需求文档中定义的全部功能模块。用户端微信小程序支持微信登录、商家浏览、购物车管理、订单提交与状态流转、收货地址管理等核心功能。管理后台实现了数据概览统计、商家管理、菜品管理、订单处理、用户管理等全部后台功能，并配备默认管理员账号 admin/admin123。数据库已预置五家商家及对应菜品数据，测试用户含订单和地址数据，开箱即可完整体验系统功能。

## 3. 工程与架构质量说明

后端采用 Spring Boot 3.2 框架搭配 MyBatis-Plus 持久层，遵循标准的 Controller-Service-Mapper 分层架构。前端管理后台基于 Vue 3 组合式 API 配合 Element Plus 组件库构建，使用 Pinia 进行状态管理。数据库选用 MySQL 8.0 存储业务数据，Redis 7 提供缓存支持。项目采用 Monorepo 结构组织代码，backend、frontend-admin、frontend-mp 三端代码独立维护，通过 Docker Compose 统一编排部署。

## 4. 工程细节与专业度说明

系统采用 JWT Token 实现身份认证，管理端和用户端分离鉴权确保接口安全。密码存储使用 BCrypt 加密算法，防止明文泄露风险。前后端均实现了完整的数据校验机制，包括参数格式校验和业务规则校验。API 设计遵循 RESTful 规范，统一封装响应格式包含 code、message、data 三要素。项目配备完整的单元测试和集成测试用例，后端使用 JaCoCo 统计测试覆盖率，前端使用 Vitest 进行组件测试。

## 5. Prompt需求理解与适配度说明

本次修复针对用户反馈的首页数据统计不实时问题进行处理。经分析发现原 Dashboard 组件仅在 onMounted 时获取一次统计数据，后续切换页面再返回时数据不会刷新。根据用户明确要求每次点击数据概览 Tab 刷新即可、不需要定时轮询的需求，最终方案采用 onMounted 配合 onActivated 双钩子实现页面激活时自动刷新数据，既满足了数据实时性需求又避免了不必要的轮询开销。

## 6. 美观度说明

管理后台界面采用 Element Plus 组件库构建，整体风格简洁现代。Dashboard 页面使用彩色统计卡片展示核心数据指标，配合圆润边角和阴影效果营造层次感。快捷操作区域采用四宫格布局，悬停时提供平滑的颜色渐变和微上浮动画反馈。全局配色以橙色为主色调呼应外卖业务特性，搭配适当的灰阶层级区分内容优先级。各页面均实现了加载状态提示、空状态占位、操作确认弹窗等交互细节，提供完整的用户体验闭环。
